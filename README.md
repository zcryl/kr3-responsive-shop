# FootballShop — контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Учебный магазин футбольной атрибутики на основе КР1. Использованы HTML, CSS (Flexbox и Grid) и небольшой JavaScript для существующих фильтров, модального окна и проверки форм. Bootstrap и другие CSS-фреймворки не используются.

## Запуск

Откройте `index.html` в браузере или запустите локальный сервер из папки проекта:

```sh
python -m http.server 8000
```

Затем откройте `http://localhost:8000`. Для проверки Lighthouse используйте локальный сервер.

## Страницы и согласованный объём

- `index.html` — вводный блок, популярные товары, новинки, преимущества, модальное окно заявки.
- `catalog.html` — карточки, фильтры по категориям и цене, таблица размеров.
- `contacts.html` — контакты и форма обратной связи.
- `product.html` и `order.html` — пустые заготовки, оставлены по решению автора проекта. Таблица показана в каталоге, форма заявки — в модальном окне главной.

Это согласованное отступление от требования методички о пяти заполненных страницах. Пустые страницы не включены в Lighthouse-аудит.

Формы работают как демонстрация: проверяют ввод и показывают результат. Данные не отправляются на сервер и не сохраняются. Реализация КР4 в этот этап не входит.

## Практика 12 — адаптивность

Отдельный `css/responsive.css` подключён после `css/style.css` на трёх рабочих страницах. На них есть `meta viewport`.

Применён Mobile First:

| Ширина | Главная | Каталог | Навигация и формы |
| --- | --- | --- | --- |
| До 768px | 1 колонка | Фильтры сверху, 1 колонка | Меню в 2 колонки, поля формы в 1 колонку |
| От 768px | 2 колонки | Фильтры сверху, 2 колонки | Меню Flexbox с переносом, форма в 2 колонки |
| От 1024px | 3 колонки | Фильтр слева, 2 колонки | Крупные поля и кнопки |
| От 1200px | 3 колонки | Фильтр слева, 3 колонки | Ограничение ширины содержимого 1100px |

- `minmax(0, 1fr)` и `min-width: 0` предотвращают переполнение сетки.
- Hero использует `clamp()` для плавного изменения заголовка и отступов.
- Карточки используют Flexbox, кнопка выравнивается вниз через `margin-top: auto`.
- `picture`, WebP и `srcset` предлагают варианты 320/640/960px; `sizes` описывает ширину изображения в раскладке.
- `max-width: 100%`, `height: auto`, `object-fit: contain` сохраняют изображения в контейнере без обрезания товара.
- 27 оптимизированных WebP находятся в `images/responsive/`; оригиналы сохранены.
- `width`/`height` резервируют место для изображений, `loading="lazy"` откладывает загрузку за пределами экрана.
- Таблица имеет собственный прокручиваемый контейнер с доступом с клавиатуры.
- Модальное окно ограничено доступной высотой экрана, поля и кнопки удобны для телефона.
- Учтён `prefers-reduced-motion`.

## Практика 13 — доступность

Найдено и исправлено:

- Логотип ошибочно был `h1` с атрибутом `href`: заменён ссылкой. На каждой рабочей странице один `h1`.
- Добавлена ссылка пропуска навигации к `main`, доступная при фокусе.
- Добавлены осмысленные `alt` для изображений; подключена предоставленная автором фотография Головина.
- Исправлен повторяющийся `id="popular"`.
- Задан отсутствовавший цвет `--color-primary`, светлый серый текст заменён более контрастным.
- Видимый фокус есть у ссылок, кнопок, полей, флажков и контейнера таблицы; на чёрной шапке — светлый контур.
- Поля связаны с подписями; обязательные поля отмечены текстом и `required`.
- Ошибки связаны с полями через `aria-describedby`; `aria-invalid` ставится только при ошибке. Фокус переходит к первому неверному полю.
- Нативный `dialog` имеет название, начальный фокус, закрытие через Escape и возврат фокуса на кнопку открытия.
- У таблицы есть `caption`, `thead`, `tbody`, `th` и `scope`.
- Ссылки каталога ведут к работающему сценарию заявки и передают название товара.
- Восстановлен существовавший, но полностью закомментированный код фильтров.
- Уведомления формы используют `role="status"`; данные обрабатываются только в браузере.

## Lighthouse

Проверка выполнена 2 ноября 2026 года локально в Chrome, категория Accessibility. Отчёты сохранены в HTML для просмотра и JSON для проверки результата.

| Страница | Accessibility | Отчёт |
| --- | --- | --- |
| Главная | 100/100 | [HTML](lighthouse/index.report.html) |
| Каталог | 100/100 | [HTML](lighthouse/catalog.report.html) |
| Контакты с формой | 100/100 | [HTML](lighthouse/contacts.report.html) |

Lighthouse проверяет не все аспекты доступности. Дополнительно в браузере проверены клавиатура, формы, модальное окно и перестроение раскладки.

## Практика 14 — итоговая проверка КР3

Проверены все три рабочие страницы на ширинах **360, 430, 768, 1024, 1440px**. Переполнения страницы по горизонтали нет; таблица прокручивается внутри своего контейнера.

Проверены:

- переход к основному содержимому и видимый фокус;
- открытие заявки клавишей Enter, фокус внутри окна, закрытие Escape и возврат фокуса;
- ошибки обязательных полей, корректный ввод и результат проверки обеих форм;
- фильтрация товаров по категории и цене, пустой результат и сброс;
- переход из каталога с сохранением названия товара;
- корректная загрузка изображений и синтаксис JavaScript.
