# Журнал изменений и подготовка к защите КР3

Дата работы: 2 ноября 2026 года.

## Согласованный объём

- Основа — FootballShop после КР1, обычные HTML, CSS и JavaScript без Bootstrap.
- `product.html` и `order.html` остаются пустыми по указанию автора проекта.
- Рабочие страницы: главная, каталог, контакты. Таблица размеров находится в каталоге, заявка — в модальном окне главной.

- КР4 не выполняется. JavaScript нужен для существующих фильтров, доступной формы и модального окна.

## 0. Сохранение исходного состояния

Исходные файлы сохранены отдельным коммитом `chore: preserve KR1 shop baseline`.
Это позволяет сравнить сайт до и после работы. Добавлен remote `origin`, указывающий на репозиторий автора.

## 1. Практика 12 — адаптивность

### css/responsive.css

- Вместо начального каркаса добавлена полноценная раскладка Mobile First: базовые правила рассчитаны на телефон.
- `@media (min-width: 768px)` включает две колонки карточек и формы; `1024px` — три колонки главной и фильтр слева в каталоге; `1200px` — три колонки каталога.
- В каталоге на 1024px остаются две колонки, чтобы боковой фильтр не сжимал карточки.
- `minmax(0, 1fr)` и `min-width: 0` разрешают блокам сжиматься внутри сетки без горизонтального переполнения.
- Навигация на телефоне — две колонки крупных ссылок, на планшете и компьютере — Flexbox с переносом. Пункты не скрываются за меню: ими можно пользоваться без JavaScript.
- Кнопки и поля имеют высоту от 44px; кнопки модального окна на телефоне идут друг под другом.
- Модальное окно ограничено высотой `100dvh - 32px` и прокручивается внутри; `dvh` учитывает доступную высоту мобильного браузера.
- Включён `prefers-reduced-motion`: плавная прокрутка отключается при соответствующей настройке пользователя.
- Не используется `overflow-x: hidden` на body: переполнение устраняется размерами элементов.

### index.html, catalog.html, contacts.html

- На главную возвращён вводный hero-блок с заголовком магазина и ссылками на каталог и популярные товары.
- Удалены старые закомментированные фрагменты разметки. Повторяющийся `id="popular"` у новинок заменён на `new-products`.
- Изображения карточек обёрнуты в `picture`; `source` задаёт WebP, `srcset` — варианты 320/640/960px, `sizes` — ожидаемую ширину карточки при разных раскладках.
- `width`/`height` резервируют место до загрузки. `loading="lazy"` откладывает загрузку изображений за пределами экрана.
- `object-fit: contain` показывает товар полностью без обрезания.
- В каталог добавлена небольшая учебная таблица размеров с `caption`, заголовками строк и колонок. Мерки ориентировочные.
- Контейнер `.table-wrapper` имеет `overflow-x: auto`, поэтому на телефоне прокручивается таблица, а не страница.

### images

- Добавлено предоставленное автором фото `golobin_shirt.webp`.
- Созданы 27 оптимизированных WebP в `images/responsive/`: по три размера для девяти товаров. Исходные фотографии сохранены.
- Квадратные версии используют белые поля и не обрезают товары.

### sitemap.xml и метаданные страниц

Ссылки со старого имени репозитория КР1 заменены на `kr3-responsive-shop`. Это адрес для возможной публикации; само наличие адреса не означает, что GitHub Pages уже включён.

### Как показать преподавателю

Открыть главную и каталог, менять ширину 360 → 768 → 1024 → 1440px. Показать перестроение карточек и фильтра, затем прокрутку таблицы на телефоне. В Network с фильтром Img и отключённым кешем показать выбранный WebP. Браузер учитывает не только ширину, но и плотность пикселей экрана.

## 2. Практика 13 — доступность и работа форм

### Семантика и навигация

- Логотип `h1 href` заменён обычной ссылкой на главную. Основной `h1` теперь относится к содержимому страницы; на каждой рабочей странице он один.
- В начало body добавлена `.skip-link`. Обычно она находится выше экрана, а при фокусе появляется. `href="#main"` переводит к основному содержимому; `tabindex="-1"` позволяет main принять фокус, не добавляя его в обычный обход Tab.
- Внешний контейнер каталога заменён с section без заголовка на div. Внутри сохранены смысловые aside и section с заголовками.
- Сохраняются `nav aria-label` и `aria-current="page"` у активного пункта меню.
- В контактах телефон и почта стали ссылками `tel:` и `mailto:`.

### css/style.css

- Добавлен отсутствовавший `--color-primary: #0057b8`: ранее ссылки на эту переменную использовались, но сама переменная отсутствовала.
- `--color-muted` изменён с #b2afaf на #555555 для читаемого серого текста на белом фоне.
- Общий `:focus-visible` делает клавиатурный фокус заметным. В чёрной шапке контур светло-жёлтый, чтобы он не терялся на фоне.
- Добавлены стили skip-link, текстовых ошибок, примечаний и строки выбранного товара.
- Подпись согласия и checkbox выровнены через Flexbox; область подписи имеет удобную высоту.

### index.html и js/main.js

- Вместо условных «Товар 1/2/3» в `data-product` записаны реальные названия.
- При открытии заявки название записывается в скрытое поле и показывается пользователю текстом. Для общей заявки отображается «Общая заявка».
- Добавлен раздел `#request` с явной кнопкой открытия формы. Раньше ссылка из контактов приводила к подвалу, где открыть форму было нельзя.
- Ссылки каталога передают товар параметром `?product=...#request`. `URLSearchParams` читает название; `textContent` выводит его как текст, не как HTML.
- `showModal()` открывает нативный dialog. Браузер ограничивает переходы Tab рамками окна и делает фон неактивным.
- `autofocus` ставит курсор в поле имени; Escape закрывает dialog. Обработчик события `close` возвращает фокус на кнопку, открывшую окно.
- Добавлено видимое пояснение об обязательных полях; `required` задаёт обязательность для браузера. Подсказка телефона связана с полем через `aria-describedby`.
- Для каждой формы перебираются только проверяемые input/select/textarea. При проверке обнаружено, что submit-кнопка также может иметь `willValidate`; фильтр по типу элемента исключает эту ошибку.
- Для полей создаются текстовые сообщения `.form-error`. Их id добавляется в `aria-describedby`, сохраняя существующую подсказку телефона.
- `novalidate` отключает автоматическое всплывающее сообщение при отправке, но не HTML-ограничения. `checkValidity()` позволяет показать ошибки в собственной разметке.
- Если поле неверно, ставится `aria-invalid="true"` и выводится `validationMessage`. Фокус переносится на первое неверное поле. При редактировании старая ошибка очищается.
- При корректном вводе форма сбрасывается, dialog закрывается и появляется сообщение с `role="status"`.
- Старое «Форма успешно отправлена» заменено точным сообщением: проверка выполнена локально. Backend отсутствует, `preventDefault()` отменяет сетевую отправку.
- Обработчики dialog подключаются только там, где окно существует; общий файл main.js также работает на странице контактов.

### contacts.html

Добавлена небольшая форма обратной связи: имя, email и сообщение. Подписи связаны с полями через for/id, используются autocomplete и required. Она подключает тот же main.js и ту же CSS-сетку. На телефоне поля идут друг под другом, на планшете имя и email расположены в две колонки. Учебная форма проверяет ввод без отправки данных.

### catalog.html и js/catalog.js

- Кнопке сброса добавлен базовый класс `.button`, чтобы размеры и фокус совпадали с другими кнопками.
- Ссылки «Подробнее», ранее ведшие к общему блоку главной, заменены понятным действием «Оставить заявку» с выбранным товаром.
- Восстановлен уже существовавший код фильтрации, который был целиком закомментирован. Новый каталог или корзина не создавались.
- Фильтр сравнивает data-category и data-price карточек с выбранными полями. Несовпавшим карточкам ставится hidden; CSS скрывает их целиком, включая ссылки.
- Пустая категория означает все категории, пустая нижняя цена — 0, верхняя — Infinity. При отсутствии совпадений появляется сообщение с role="status".
- Если нижняя цена больше верхней, `setCustomValidity()` задаёт понятное сообщение. При вводе исправленного значения оно очищается. Reset показывает все девять товаров.

### Lighthouse

В `lighthouse/` сохранены настоящие отчёты Lighthouse для главной, каталога и контактов: HTML для открытия в браузере, JSON для машинной проверки. У всех трёх Accessibility — 100/100. Пустые product.html и order.html не проверялись. Автоматический балл дополнен ручной проверкой клавиатуры и сценариев форм.

1. Объяснить основу: «Это мой FootballShop после КР1. В КР3 я адаптировал его на чистом CSS и проверил доступность».
2. Открыть responsive.css и показать базовую одну колонку, затем медиазапросы min-width. Объяснить, почему в каталоге с фильтром на 1024px две колонки.

## 5. Ответы на вероятные вопросы

- **Зачем отдельный responsive.css?** Основной файл хранит оформление компонентов, отдельный — правила изменения раскладки. Он подключён последним и переопределяет прежние размеры.
- **Чем Grid отличается от Flexbox?** Grid задаёт сетку строк и колонок; Flexbox удобен для меню, кнопок и вертикального содержимого карточки.
- **Зачем viewport?** Он сообщает мобильному браузеру использовать реальную ширину устройства, чтобы медиазапросы срабатывали ожидаемо.
- **Почему min-width?** Мобильный вариант задан по умолчанию; более сложная раскладка добавляется при наличии места.
- **Зачем alt и label?** Alt передаёт смысл фотографии без её просмотра; label называет поле и позволяет выбрать его нажатием по подписи.
- **Зачем ARIA?** Для информации, которой не хватает обычному HTML: текущий пункт, связь ошибки с полем, уведомление о результате. Нативные button, dialog и table сохраняют свою семантику.
- **Почему таблица имеет tabindex?** Её контейнер можно сфокусировать и прокручивать с клавиатуры.
- **Что делает JavaScript в КР3?** Поддерживает уже существующие фильтры и dialog, показывает ошибки доступным способом. Корзина, localStorage, backend и другие задачи КР4 не добавлялись.
- **Куда отправляется заявка?** Никуда: это учебная демонстрация frontend, обработчик отменяет отправку, проверяет ввод и показывает статус.
